## Project state

A desktop resume (CV) generator built on **Tauri 2 + vanilla HTML/CSS/JS**. The code is still the stock `create-tauri-app` vanilla template: the `greet` command and the welcome page are placeholders to be replaced. The design spec for the real app is `docs/mockup.html` (see below).

## Commands

There is no `package.json` and no JS toolchain. The frontend is served as-is, and the Tauri CLI is not installed globally. Run Tauri commands from the repo root (the CLI finds `src-tauri/` itself) with either:

```bash
npx @tauri-apps/cli@2 dev
```

```bash
npx @tauri-apps/cli@2 build
```

or install the Cargo subcommand once (`cargo install tauri-cli --version "^2"`) and use `cargo tauri dev` / `cargo tauri build`.

Rust-only checks run against `src-tauri/Cargo.toml`:

```bash
cargo check --manifest-path src-tauri/Cargo.toml
```

```bash
cargo clippy --manifest-path src-tauri/Cargo.toml
```

```bash
cargo test --manifest-path src-tauri/Cargo.toml
```

Run a single test with `cargo test --manifest-path src-tauri/Cargo.toml <test_name>`. No tests exist yet, and nothing is set up for linting or testing the JS.

## Architecture

- **No bundler.** `tauri.conf.json` sets `build.frontendDist` to `../src` with no `devUrl` or `beforeDevCommand`, so the files in `src/` are loaded directly. `src/main.js` is a plain ES module. A dependency would have to be vendored into `src/`, or a bundler (and a `devUrl`) added.
- **Tauri API via a global.** `app.withGlobalTauri: true` injects `window.__TAURI__`, which the frontend uses in place of `@tauri-apps/api` imports (e.g. `const { invoke } = window.__TAURI__.core;`).
- **Rust side.** All app logic lives in `src-tauri/src/lib.rs` (crate lib name `app_lib`). `main.rs` only calls `app_lib::run()` and must keep its `windows_subsystem` attribute. A new command needs `#[tauri::command]` and an entry in `tauri::generate_handler![...]`. Its JS `invoke` arguments are camelCase versions of the Rust parameter names.
- **Permissions.** `src-tauri/capabilities/default.json` grants permissions to the `main` window. Each plugin you add (fs, dialog, etc.) needs both `.plugin(...)` in `lib.rs` and its permissions listed there, or its calls are rejected at runtime. `src-tauri/gen/schemas` is generated by the build and git-ignored.
- **CSP** is currently disabled (`security.csp: null`).

## Design mockup (`docs/mockup.html`)

The mockup is a ~2.6 MB self-unpacking bundle, so don't read it whole. The UI template and its component logic are a JSON-encoded string on line 384 (a `<script type="__bundler/template">` block). Decode that one line (JSON-parse it, then HTML-unescape it) and grep the result. Line 372 holds the bundled assets.

What it specifies:

- **Language:** the UI is in Brazilian Portuguese (pt-BR).
- **Look:** GTK/libadwaita style; its storage key is `cvgen-gtk:v1`. The mockup draws its own window controls (minimize, maximize, close) and a light/dark theme toggle.
- **Screens:**
  - Resume list: folders in a sidebar, and resumes can be dragged onto a folder or moved with "Mover para".
  - Editor: a form pane next to a paginated A4 preview with zoom and page breaks.
  - Settings: the storage folder for resumes and exported PDFs, and an app reset.
  - Export-PDF dialog: file name, folder, A4 paper, clickable links, and an "open after export" option.
- **Data model:** the header (name, title, ordered contact fields) is always first, followed by reorderable sections.
  - Section types (`TYPES`): summary, skills, experience, education, courses, projects, languages, certifications, publications, awards, custom. Each type turns entry fields (title, subtitle, date range or single date, location, link, rich-text description) on or off.
  - Contact fields (`CONTACT`) are grouped into contact, personal data and links/social. Empty fields are left out of the rendered resume.
  - Each section and each entry has a "show in resume" toggle.
